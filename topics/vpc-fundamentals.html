VPC Fundamentals

A VPC is the foundation of Google Cloud networking. It is a global virtual network that lets you segment resources, define private IP space, control traffic with firewall rules, and connect services securely within a project or across projects.

What a VPC really is

In Google Cloud, a VPC network is a global resource, while subnets live in a specific region. This means you can create one VPC and then place regional subnets within it to support workloads in multiple locations without changing the design of the network itself.

Key idea

Think of the VPC as the network boundary, and subnets as the regional building blocks inside that boundary. Firewalls and routes are what shape how traffic can move between those resources.

Core concepts

  • Global network: One VPC can span multiple regions.
  • Regional subnets: Each subnet belongs to one region and has a CIDR block.
  • Firewall controls: Ingress and egress rules determine which traffic is allowed.
  • Routes: GCP automatically creates system routes, and custom routes can be added for special traffic patterns.

Why this matters for the exam

Most networking questions are really about choosing the right architecture pattern: private-only access, isolation by segment, east-west traffic control, and hybrid connectivity. A good VPC design makes route tables, firewall policies, and service access predictable and secure.

Exam traps to avoid

  • Confusing a VPC being global with a subnet being global. Subnets are regional.
  • Assuming all traffic is allowed by default. Firewall rules are the main access control mechanism.
  • Forgetting that communication within a VPC may still require correct firewall and routing behavior.
