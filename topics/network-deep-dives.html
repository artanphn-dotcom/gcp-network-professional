Network Topic Deep Dives

These are the advanced networking topics most often tested in the Professional Cloud Network Engineer exam. Each one is a high-value area where architecture decisions, route behavior, hybrid connectivity, and security design matter.

High-value deep-dive topics

Organizational constraints

Organization policies can limit networking design by preventing external IPs, restricting VPC peering, or forcing governance around how projects and services can be connected. For the exam, know that policy constraints can override default design choices.

  • Review default restrictions and exceptions.
  • Understand how project-level security controls affect network architecture.
Read official documentation

Shared VPC

Shared VPC allows a host project to share a VPC network with other projects. This is important for centralized network administration, consistent firewall policies, and multi-project environments that need common network services.

  • Use it when multiple teams or services need a common VPC without duplicated network design.
  • Know the difference between host project and service project responsibilities.
Read official documentation

Private Service Access and Private Google Access

Private Service Access allows private, internal access to managed services such as Google APIs or internal services over private IP space. Private Google Access lets VMs without external IP addresses reach Google APIs and services over the VPC network.

  • Private access is critical for workload isolation and reduced exposure.
  • Understand when private-only access is a better design than public egress.
Private Service Access · Private Google Access

Cloud Router

Cloud Router is the BGP-enabled routing component used for dynamic route exchange with on-premises networks and partner networks. It is central to Hybrid Connectivity, Interconnect, and VPN design.

  • Understand how route propagation works and why dynamic routing matters.
  • Know how Cloud Router integrates with VPN and Interconnect for redundancy and scalability.
Read official documentation

DNS best practices

DNS is not just name resolution. In cloud networking, DNS design affects load balancing decisions, service discovery, private zone isolation, and cross-environment routing. Good DNS patterns improve resilience and reduce failed lookups.

  • Use private DNS for internal-only workloads.
  • Keep authoritative names and split-horizon design clear and intentional.
Read official documentation

Choosing a load balancer

Network engineering questions often test whether you know when to use Global HTTP(S), Regional TCP/UDP, Internal Load Balancing, or Ingress for Kubernetes. The decision is driven by protocol, exposure model, and traffic characteristics.

  • Use HTTP(S) load balancing for web traffic and global scale.
  • Use internal TCP/UDP balancing for private service access and app tiers.
Choosing a load balancer · Ingress

Internal LB and next hop with NVA

Internal load balancers are frequently used to expose services only inside a VPC or between networks. When paired with a Next-Hop firewall or NVA, they can be used to steer traffic through security appliances or centralized inspection layers.

  • Know when the architecture uses private frontends for internal apps.
  • Understand how appliance routing can be used for centralized filtering.
Read official documentation

Networking on GKE

Google Kubernetes Engine networking includes cluster IP ranges, pod networking, node networking, and service exposure. VPC-native clusters are usually the default pattern for modern, scalable Kubernetes networking on GCP.

  • Understand alias IPs and VPC-native networking in cluster design.
  • Know how ingress and services map to backend pods.
GKE networking overview · VPC-native clusters

Hybrid connectivity options

Hybrid connectivity is the set of ways to connect on-prem environments to Google Cloud. The main choices are VPN, Interconnect, and Network Connectivity Center, depending on bandwidth, latency, and operational needs.

  • Choose VPN for lower complexity and cost.
  • Use Dedicated Interconnect for high-performance private connectivity.
Read official documentation

Dedicated Interconnect and dual stack

Dedicated Interconnect provides private connectivity with predictable bandwidth and lower latency. Dual stack support matters for IPv4 + IPv6 workloads or mixed network environments that need both protocols.

  • Know the provisioning process and attachment design.
  • Understand the business case for highly available and performance-sensitive paths.
Dedicated Interconnect · Dual stack support

HA VPN

HA VPN provides highly available VPN connectivity between Google Cloud and on-premises sites. It is the common solution when you want redundancy and a simpler setup than a full private connectivity design.

  • Good for resiliency and failover without the complexity of dedicated circuits.
  • Easier to operate than full physical interconnect deployments.
Read official documentation

Cross-Cloud Network for distributed applications

Cross-cloud patterns are used when applications span multiple public clouds or connect cloud environments with on-prem systems. The key design concerns are distributed routing, latency, and secure connectivity between domains.

  • Think about network segmentation, policy enforcement, and traffic paths.
  • Use this pattern when global application reach and data locality matter.
Read official documentation

Cloud CDN

Cloud CDN accelerates content delivery by caching content at Google edge locations. It improves response time for static and some dynamic assets while reducing origin load.

  • Useful for frontend application acceleration and content-heavy workloads.
  • Requires thought about cache invalidation and origin freshness.
Read official documentation

Invalidations

Cache invalidation is the process of removing stale content from the edge cache so clients receive fresh data. For content-heavy and frequently updated services, this is a critical operational concept.

  • Understand how stale caches affect application behavior.
  • Know the difference between purging and expiration strategies.
Read official documentation

NGFW

Next-generation firewalls are often used for centralized network inspection in cloud environments. They sit at strategic control points where traffic inspection, filtering, and threat analysis are required.

  • Fits enterprise environments that need stronger perimeter controls.
  • Common in hub-and-spoke models with centralized inspection.
Read official documentation

Cloud Armor

Cloud Armor is a managed DDoS and application defense product that protects services from common web attacks and abusive traffic patterns. It is especially useful when front ends are public-facing.

  • Review rules for IP allowlists, rate limiting, and geo restrictions.
  • Know how it complements load balancers and edge security controls.
Read official documentation

Cloud NAT

Cloud NAT provides outbound internet access for private resources without assigning external IPs to each VM. It reduces public exposure and helps with egress design in private-only environments.

  • Use it when private instances need outbound internet access.
  • It is different from inbound connectivity and should not be confused with public ingress.
Read official documentation

VPC

VPC is the foundation of GCP network design. A well-built VPC uses segmentation, private IP planning, route control, and policy boundaries to support scalability, security, and service integration.

  • Know the relationship between global VPC design and regional subnet layout.
  • Examine how firewall rules and custom routes shape network behavior.
Read official documentation

VPC Service Controls

VPC Service Controls create a security perimeter around GCP services to protect data from exfiltration or unauthorized access. This matters when you need to enforce service-level access boundaries for sensitive data workloads.

  • Useful for regulated or highly sensitive services.
  • Important when securing data access across multiple services and project boundaries.
Read official documentation

Network Intelligence Centre

Network Intelligence Centre provides insight into connectivity, performance, and service health across your Google Cloud network. It helps identify latency, topology issues, and service reachability concerns.

  • Useful for validating network health and troubleshooting complex topologies.
  • Helps in network operations and performance review.
Read official documentation
